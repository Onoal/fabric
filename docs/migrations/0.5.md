# Migrating from Fabric 0.4.x to Fabric 0.5

Fabric 0.5 presents the architecture that matured through the 0.4 line as one
normal authoring path. The intent is not to change what Resources, Systems,
Adapters, Components, Compositions, or Instances mean; it is to remove legacy
ceremony from the path new code follows.

## Semantic API

Replace the legacy explicit primary-contract form with `api`:

```rust
// 0.4.x legacy compatibility form
contracts {
    primary Api {
        id: "example.store.api";
        fn get(&self, key: String) -> Option<String>;
    }
}

// Canonical form
api {
    fn get(&self, key: String) -> Option<String>;
}
```

The primary API identity and version derive from the Resource or System owner.
Do not add a second normal-path API id or version.

## Adapter target

Replace target-kind and generated-interface ceremony with the target type:

```rust
// Legacy explicit form
adapter! {
    Memory for resource Store implements StoreRealization { /* ... */ }
}

// Canonical form
adapter! {
    Memory for Store { /* ... */ }
}
```

The target determines whether it is a Resource or System and supplies the
normal realization requirement. Ordinary Rust resolution applies, so imported,
aliased, re-exported, and fully-qualified targets are equivalent.

## Direct and differential realization

When an Adapter implements the public API directly, write its methods once in
the Adapter. Do not add a Resource/System forwarding runtime.

When a semantic owner deliberately mediates part of its API, declare only the
delta: mediated API methods and realization-only operations. The semantic
provider assembles the complete public API; the Adapter provides the effective
realization contract. Consumers continue to see only the semantic API.

## Runtime ownership

`state`, `runtime`, and `lifecycle` do not belong to every Resource or System.
Use them only when that semantic subject owns a self-realization or a genuine
semantic mediation layer. Concrete connection pools, processes, sockets, and
their lifecycle/health belong to an Adapter realization. `Config` remains
immutable declarative input, never mutable runtime state or live control.

## What does not change

Composition remains declarative truth; Instance remains one materialized,
generation-scoped runtime. Lifecycle remains `Ready -> Running -> Stopped` for
an Instance generation, `stop` remains fallible deterministic cleanup, and
health remains independent from lifecycle. Relations remain semantic
requirements, while Host requirements remain concrete-realization compatibility.

Fabric 0.5 removes those legacy high-level parser paths. Migrate the affected
declarations to the canonical forms above; advanced handwritten contracts and
providers remain available explicitly through `fabric::authoring` and
`fabric::core`.
