# Fabric 0.4.0

## Overview

Fabric 0.4.0 completes Lifecycle as a cross-cutting runtime spine while
preserving the existing Resource, System, Component, Adapter, Host,
augmentation, and Core semantic boundaries.

## Lifecycle spine

Composition remains immutable declarative truth. Each materialization creates
an Instance generation with the narrow `Ready -> Running -> Stopped` lifecycle;
`Stopped` is terminal and a new run requires fresh materialization. A runtime
participant is materialized, bound, initialized, started, and stopped. Lifecycle
is distinct from Health and from package/domain state.

## Deterministic cleanup

Every successfully materialized runtime occurrence receives best-effort,
reverse-dependency-order cleanup through fallible `stop`, including when
context binding, initialization, or startup fails. Cleanup errors remain
observable without replacing the initiating failure.

## Stateful runtime authoring

Normal Resource, System, and Adapter authors can own fresh runtime state,
runtime context, initialize/start/stop hooks, and health reporting through the
public SDK and optional macro `state` / `lifecycle` sections. Configuration is
not runtime state; contract handles within an occurrence share its state, while
each materialization receives a fresh state occurrence.

## Component lifecycle alignment

The Component host lifecycle is `Starting -> Ready -> Stopping -> Stopped`.
During abandoned startup it follows `Starting -> Stopping -> Stopped`. Host
health is independent, so a ready host may be healthy, degraded, or unavailable.
Dynamic Component participation remains `Preparing -> Active -> absent` and
preparation may own occurrence-local teardown. Base and augmentation teardown
is reverse preparation order and runs on rollback, dematerialization, and host
stop.

## Public API changes

This minor release intentionally changes advanced Core lifecycle APIs:

- `ModuleRuntime::stop` returns `Result<(), ModuleError>`.
- `Instance::stop` and `FabricInstance::stop` return cleanup results.
- `InstanceError::ModuleFailure` and relevant materialization errors can retain
  cleanup evidence alongside the primary error.
- `ComponentRuntimeLifecycle::Degraded` is removed. Use `Ready` lifecycle with
  `Health::Degraded` instead.

## Package pressure proof

The public authoring model now supports a downstream LocalProcess Adapter with
per-generation child-process state and deterministic Instance-stop cleanup,
without author-written raw `ModuleRuntime`. This is lifecycle machinery, not a
ProcessRuntime semantic built into Fabric.

## Non-goals

Fabric 0.4.0 does not add a scheduler, restart or recovery policy, deployment
orchestration, a global lifecycle manager, a runtime registry, or new package
ontology.

## Install

```toml
[dependencies]
fabric = { package = "onoal-fabric", version = "0.4.0" }
```
