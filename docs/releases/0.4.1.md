# Fabric 0.4.1

## Overview

Fabric 0.4.1 is a backwards-compatible authoring-DX patch. It keeps the 0.4
lifecycle spine and Fabric ontology unchanged while removing normal-definition
ceremony that Fabric can derive safely.

## Normal authoring

Resource and System definitions now use `version: "...";` as the normal
author-facing semantic version. Omitting it selects provisional semantics.
Their primary contract inherits that version when its own version is omitted,
and an empty `config {}` section may be omitted.

Adapter authors use `version: "...";` for their provider-contract version.
The Adapter's target support is inferred exactly from the Resource or System
named by its header. Use `supports: "...";` only when the implementation
intentionally supports a wider target version range.

## Compatibility

Existing 0.4.0 macro forms remain valid, including explicit `schema: ...;`,
`realization: ...;`, contract versions, and `config {}`. Those forms remain
available for advanced compatibility control; ordinary definitions no longer
need to repeat provisional/schema machinery.

Resource and System dependencies still express real consumer intent explicitly.
For example, a consumer of a versioned `0.1.0` contract should require an
appropriate version range rather than `provisional`.

## Boundaries

This release does not change Resource, System, Component, Adapter, Host,
Composition, Instance, augmentation, lifecycle, health, or runtime-state
semantics. It adds no scheduler, restart/recovery policy, runtime registry, or
new semantic ontology.

## Install

```toml
[dependencies]
fabric = { package = "onoal-fabric", version = "0.4.1" }
```

```rust
use fabric::*;
```
