# Fabric 0.4.3

Fabric 0.4.3 establishes universal typed Config authoring for Resources,
Systems, and Adapters.

## Config is creator-to-consumer input

A definition creator declares the typed choices a consumer may provide while
selecting a semantic occurrence or constructing a realization. Config is
immutable declarative input; it is not runtime state, live control, lifecycle,
identity, or compatibility.

- Omit `config` when there is no Config: Resource selection, System selection,
  and Adapter construction then take no empty Config value.
- Use `config { ... }` for a concise inline public Config type generated by
  Fabric.
- Use `config: MyConfig;` when an ordinary creator-owned Rust type should be
  the public Config contract. This supports enums, nested types, constructors,
  and Rust-level validation without a Fabric-specific configuration language.
- Resource/System semantic Config and Adapter realization Config remain
  independently owned and compose without collision.

Generated runtime methods and lifecycle hooks read their selected Config with
`self.config()`. Live mutable machinery remains runtime state.

## Compatibility

Existing explicit `config {}` declarations remain supported. New normal
authoring omits Config entirely when it has no choices.

Fabric 0.4.3 changes no lifecycle or ontology semantics and adds no Config
registry, serialization requirement, or live reconfiguration mechanism.

## Install

```toml
[dependencies]
fabric = { package = "onoal-fabric", version = "0.4.3" }
```

```rust
use fabric::*;
```
