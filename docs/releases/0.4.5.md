# Fabric 0.4.5

Fabric 0.4.5 establishes canonical semantic API authoring for Resources and
Systems.

## Semantic API authoring

New normal definitions use one `api { ... }` section:

```rust
fabric::resource! {
    KeyValueStore {
        id: "example.key-value";
        version: "1.2.0";
        api {
            fn get(&self, key: Vec<u8>) -> Result<Option<Vec<u8>>, KeyValueError>;
        }
        runtime { /* self-runtime methods, where applicable */ }
    }
}
```

Fabric lowers that API to the existing typed primary-contract machinery. Its
identity is derived deterministically from the Resource or System owner, and
its version follows the owner's semantic version. Omitted owner version remains
provisional. `api {}` is an explicit marker API.

Relations continue to target the generated semantic API, so Config, Relations,
API, and Runtime remain independent authoring facets. The normal API grammar is
identical for Resources and Systems.

## Compatibility

The explicit `contracts { primary ... }` form remains supported as a legacy
compatibility syntax in the 0.4 line. It is no longer the documented normal
path. Existing realization contracts, Adapter headers, and runtime forwarding
remain intentionally unchanged; their simplification is separate work.

## Install

```toml
[dependencies]
fabric = { package = "onoal-fabric", version = "0.4.5" }
```
