# Fabric 0.4.8

## Import-independent canonical Adapter targets

Fabric 0.4.7 introduced canonical `adapter! { Adapter for Target { ... } }`
authoring. Its initial lowering incorrectly reconstructed generated API module
paths from the written target token. As a result, a target imported, renamed,
or re-exported into an Adapter author's scope could fail to compile.

Fabric 0.4.8 removes that source-layout assumption. Canonical Adapter lowering
now reaches target-owned API bridge machinery through the Rust-resolved target
type. The normal syntax is unchanged:

```rust
use target_def::Store as ImportedStore;
use fabric::*;

adapter! {
    MemoryStore for ImportedStore {
        runtime {
            fn get(&self) -> usize { 1 }
        }
    }
}
```

Local, fully qualified, imported, renamed, re-exported, and nested-module
target paths are equivalent. The API remains the default realization contract;
no explicit `implements` ceremony or Resource/System forwarding runtime has
returned.

Fabric 0.4.7 remains published and immutable, but is superseded for canonical
Adapter use by 0.4.8.

## Install

```toml
[dependencies]
fabric = { package = "onoal-fabric", version = "0.4.8" }
```
