# Fabric 0.4.9

## Composed providers and differential realization

Fabric 0.4.9 adds typed derived providers: one provider may export a typed
capability assembled from ordinary typed required capabilities. Core continues
to select one provider per contract; it does not select providers per method.

This enables optional differential realization for Resources and Systems. The
public API remains the default Adapter contract. When a semantic owner needs
to mediate one method, `realization` states only the delta:

```rust
resource! {
    DocumentStore {
        id: "example.document-store";
        api {
            fn read(&self, key: String) -> String;
            fn write(&self, key: String, value: String) -> usize;
        }
        realization {
            mediate read;
            fn read_bytes(&self, key: String) -> Vec<u8>;
        }
        runtime {
            fn read(&self, key: String) -> String {
                String::from_utf8(self.realization.read_bytes(key)).expect("utf8")
            }
        }
    }
}
```

An `adapter! { Concrete for DocumentStore { ... } }` provides `write` and
`read_bytes`; consumers still receive only `read` and `write`. Normal direct
Adapter authoring is unchanged, remains type-resolved for imported and aliased
targets, and still requires no `implements` declaration.

Semantic API identity and version remain owner-derived. The effective
realization contract is internal and deterministically derived from the
semantic owner and its version. A pure semantic assembly has no independent
state, lifecycle, or health; Adapter state and lifecycle remain Adapter-owned.

## Install

```toml
[dependencies]
```
