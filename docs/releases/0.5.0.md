# Fabric 0.5.0

Fabric 0.5.0 freezes one public authoring language around the architecture
established during the 0.4 line: semantic subjects declare their API;
realizations provide live machinery; Compositions select declarative truth;
Instances materialize one generation of that truth.

## Canonical authoring

Resources and Systems now declare one semantic surface with `api { ... }`.
Its identity and version derive from the owning Resource or System. A normal
Adapter names only its target:

```rust
use fabric::*;

resource! {
    Store {
        id: "example.store";
        api { fn get(&self, key: String) -> Option<String>; }
    }
}

adapter! {
    MemoryStore for Store {
        runtime {
            fn get(&self, _key: String) -> Option<String> { None }
        }
    }
}
```

The target supplies the typed default realization contract. Adapter target
expansion is type-driven, so local, imported, aliased, re-exported, and
fully-qualified targets are equivalent.

## Realization ownership

Resource and System remain semantic subjects. A self-realizing subject may own
state, runtime behavior, lifecycle hooks, and health. A direct Adapter owns
that concrete live machinery for an adapted subject. Differential realization
adds a typed semantic provider only when the semantic owner explicitly
mediates part of its API; Core still selects one provider per typed contract,
not one provider per method.

## Migration from 0.4.x

Fabric 0.5 removes the legacy high-level forms:

- `contracts { primary ... }` becomes `api { ... }`.
- `adapter! { Name for resource/system Target implements Interface }` becomes
  `adapter! { Name for Target }`.
- Whole duplicated realization declarations become a direct Adapter or an
  explicit differential realization delta.
- `schema:` is no longer normal Resource/System/Adapter authoring; omit a
  version for provisional semantics or use `version:` on the semantic owner.

The semantic ontology and lifecycle laws do not change: Config remains
declarative input, state remains occurrence-local live data, lifecycle remains
separate from health, and `stop` remains fallible deterministic cleanup.

Handwritten contracts, providers, and raw orchestration remain available as
explicit advanced APIs under `fabric::authoring` and `fabric::core`; they are
not part of normal `use fabric::*` authoring.

Read the complete [0.5 migration guide](../migrations/0.5.md), the
[Getting Started guide](../getting-started.md), and the
[architecture guide](../architecture.md).
