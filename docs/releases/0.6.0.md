# Fabric 0.6.0

Fabric 0.6.0 releases the converged Component architecture. Component is a
semantic behavioral participant with a declaration, an optional realization,
and a generation-scoped live occurrence.

## Canonical Component authoring

A Component declares only the semantic axes it uses: identity and optional
Config, Relations, and API. It becomes live only through a realization.

```rust
use fabric::*;

component! {
    Worker {
        id: "example.worker";
        api { fn greet(&self, name: String) -> String; }
        runtime {
            fn greet(&self, name: String) -> String {
                format!("hello {name}")
            }
        }
    }
}
```

`runtime` supplies the default self realization for one
`ComponentParticipation`. An explicit Adapter supplies a selected replacement
realization with the same participation model:

```rust
adapter! {
    RemoteWorker for Worker {
        runtime {
            fn greet(&self, name: String) -> String { format!("remote {name}") }
        }
    }
}
```

Normal users work through `component!`, `adapter!`, and `use fabric::*`.
Live participation, invocation, host/operator, and handwritten realization
APIs remain available through deliberate named modules.

## Breaking Component authoring changes

The previous Component frontend has been removed. Use these replacements:

- `requires { ... }` and `system { ... }` become
  `relations { requires { role: Target; } }`.
- `operations { ... }`, handler closures, and manual operation/type identities
  become `api { fn ...; }` plus a matching `runtime { fn ... { ... } }`.
- Top-level `teardown { ... }` moves inside `runtime`.
- `context: invocation` has no macro-level replacement; invocation provenance
  remains an advanced invocation API.

Canonical generated endpoints are exposed as `component_module::api::method()`.
Operation machinery remains lower-level typed invocation infrastructure.

## Foundations preserved

Resource, System, Adapter, Core, Config, Relations, state, lifecycle, health,
and typed differential realization retain their established semantics. Core
continues to resolve one typed provider per contract; 0.6.0 does not introduce
method-level provider selection.

