# Fabric Versioning

Fabric remains on major version 1 for the current product generation.

A minor Fabric release may intentionally contain breaking public API changes
when those changes are explicitly approved by project architecture and release
governance. Such releases must clearly document their compatibility impact and
migration path.

Breaking API changes must not be introduced silently. They also must not cause
an automatic major-version decision. Version selection is explicit project
policy, not an autonomous coding-agent decision.
